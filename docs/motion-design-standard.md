# 전문 모션그래픽 제작 기준

사용자 요청 또는 콘텐츠 목적에 따라 모션그래픽을 선택했을 때 적용한다. 로고·정보 시각화·타이포·UI·루프의 공통 기준이며 광고 목적일 때는 [광고 공통 기준](advertising-creative-standard.md)도 적용한다. 광고의 실사풍 기본값은 유지한다. 도구 이름·효과 수·모델 이름으로 실력을 증명하지 않는다.

장르를 선택할 때 [장르별 부록](motion-genres.md), 설계·납품 때 [정량·납품 기준표](motion-delivery-spec.md), 검수 때 [2층 검수 절차](motion-review-protocol.md)를 읽는다. 수치 기준표의 스튜디오 권장값은 공인 규격과 구분하고 대상·목적에 맞춘 변경 이유를 기록한다.

## 제작 순서와 전체 리듬

1. 한 문장 콘셉트, 시청자의 이해/감정 변화, 장르, 출력 비율과 플랫폼을 정한다. 같은 카드의 제목·색만 바꾸는 프레젠테이션으로 이야기를 대신하지 않는다.
2. 시작·중간·회수의 서로 다른 스타일 프레임으로 타이포·구도·색·재질·빛·깊이 시스템을 정한다. 실제 글꼴의 한글 줄바꿈·자간·행간·기준선과 가림을 설계한다.
3. 스토리보드에 사건, 주시 대상, 새 정보, 다음 장면 이유, 읽기 구간을 배치한다.
4. **본 애니메이션 전에 애니매틱**을 만든다. 거친 컷·간단한 이동·임시 자막과 실제 사용 가능한 음악 또는 표시된 임시 음악으로 전체 길이와 첫 1~3초를 점검한다. 음악 사용/최종 납품 권리는 별도로 확인한다. BGM 기본 사용, 생략은 창작 이유를 내부 기록한다. 무음판도 점검한다. 음악이 있으면 BPM·박자·시작 오프셋과 강조 비트를 기록하되 모든 컷을 비트에 강제하지 않는다. 템포가 변하면 구간별 그리드를 쓴다.
5. Producer가 기존 자동 제작 위임 안에서 애니매틱의 정보 공백·읽기 시간·구도 반복을 수정하고 모션 토큰/레이어 타임라인을 확정한다. 단계별 재승인을 요구하지 않는다. 관찰하지 못한 부분은 미확인으로 기록하면서 가능한 구현을 계속한다.
6. 본 애니메이션 → 3초 훅/8초 시제품(전체가 더 짧으면 전체) → 본편 → 자동 증거 → 가능한 수정 → 독립 정상 속도 검수 순으로 확장한다. 완성 렌더의 앞부분을 추출한 파일은 프리뷰이며 사전 애니매틱을 대체하지 않는다.

## 브랜드 모션 시스템

`motion_tokens`에 지속시간·이징·스태거·강조 위계를 정의한다. 시작 예시(스튜디오 권장)는 short 0.12~0.20초, medium 0.25~0.45초, long 0.60~0.90초, stagger 0.04~0.08초다. 실제 fps에 맞춰 프레임으로 양자화하고 결정한 값을 기록한다. long은 텍스트 최소 읽기 시간과 다른 개념이다. 같은 토큰을 모든 장르/장면에 강제하지 않는다.

주력 곡선 예시는 정착 `cubic-bezier(0.16,1,0.3,1)`, 연결 `cubic-bezier(0.65,0,0.35,1)`이다. 스프링은 필요한 물체에만 mass/stiffness/damping 또는 도구의 실제 파라미터로 정의한다. 구체적 토큰 선택과 예외 이유를 기록한다. 개별 장면 이징 목록만으로 시스템을 대신하지 않는다.

주 움직임은 현재 메시지를 전달하고, 보조 움직임은 주 움직임을 받아 다음 정보를 안내하며, 3차 움직임은 분위기/물성을 보조한다. 한 순간 주시 대상은 하나다. 모든 레이어가 같은 강도로 동시에 움직이지 않게 시작·겹침·정착을 안무한다.

## 구현과 마감

- 레이어별 시간·상태값·실제 이징, 오프셋·겹침, 마스크/변형, 시선 이동, 정보 공개와 멈춤 이유를 기록한다. 예상 동작·추종·오버슈트는 물체와 목적에 맞게 선택하며 동일 선형 이동/바운스로 일괄 처리하지 않는다.
- 형태 변형·타이포 전환·매치컷·매트·패럴랙스·깊이 중 메시지를 명료하게 하는 방식을 선택한다. 입장 애니메이션 뒤 이유 없는 긴 정지 카드가 반복되면 사건부터 다시 설계한다. 읽기·데이터 비교·로고 식별에 필요한 정착은 유지한다.
- 실제 렌더에서 모션 블러·안티앨리어싱·알파 가장자리·가림·서브픽셀 떨림·빛/그림자와 시작/끝 마감을 점검한다. 효과의 존재를 품질로 세지 않는다.
- 소리의 선행/후행, 가속·충돌·정착과 음악의 강약을 연결한다. 반복 Whoosh로 모든 전환을 처리하지 않는다. 자막과 핵심 시각 정보로 무음에서도 메시지가 성립하도록 설계한다.
- 현재 연결·승인된 도구 중 요구한 운동/합성에 맞는 방식을 선택한다. Remotion이면 제공된 remotion-best-practices와 실제 런타임을 확인한다. Blender는 공간/물리/가림 의미가 있을 때 사용한다. Pillow/FFmpeg도 표현을 구현할 수 있지만 정적 도형·페이드·줌만으로 전문 품질을 주장하지 않는다. 도구 미연결은 해당 실행만 BLOCKED다.

## 인계와 품질 판정

`motion_design` 인계에는 `genre`, `concept`, `style_frames`, `storyboard`, `animatic`(파일·해시·길이·임시 소스 여부·미확인 항목), `typography`, `composition`, `motion_tokens`, `layer_timeline`, `easing`, `transition_logic`, `beat_grid`, `sound_cues`, `silent_view_plan`, `delivery_spec`, `render_settings`, `editable_sources`, `review_evidence`, `observed_issues`를 포함한다. 이는 운영 패킷이며 기존 MOTION 원장 스키마를 임의 변경하라는 뜻이 아니다. 파일·소스·실제 렌더와 변경 버전을 보존한다.

자동 측정은 결함 탐지와 수정의 근거이며 실제 시청·청취를 대체하지 않는다. 미시청은 `AWAITING_HUMAN_REVIEW`, 해당 관찰 QA는 BLOCKED로 남기고 제작 전체를 중단하지 않는다. 마지막에 제작자와 다른 사람이 현재 파일을 정상 속도로 보고 듣고 무음판을 확인해야 최종 Viewer 판정을 내린다. 사용자 사전 승인과 실제 시청 기록을 구별한다. 기존 모든 현재 QA PASS 전 FINAL 금지 규칙을 유지한다.

비교는 같은 브리프·길이·장르의 **실제 비교 기준작**으로 수행한다. 타이포·구도·운동·리듬·마감·소리의 좋은 점/부족한 점을 타임코드로 기록한다. 비교작이 없어도 제작·수정은 진행한다. [3단계 루브릭](motion-review-protocol.md#3단계-루브릭)의 탁월 판정도 모델 우월성이나 시청률 보장이 아니다.

현재 엔진의 장르별 출고/애니매틱 지원 범위는 [검수 절차의 적용 범위](motion-review-protocol.md#현재-엔진의-적용-범위)를 확인한다. 장르별 기준을 엔진의 연결/최종 출고 지원과 등치하지 않는다.
