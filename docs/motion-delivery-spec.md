# 정량·납품 기준표

확인일: 2026-10-02. **공식 기준**, **스튜디오 권장값**, **미확인**을 구분한다. 권장값은 첫 설계용이며 합격을 보장하지 않는다. 사용자가 지정한 대상·플랫폼·장르·납품서가 우선한다. 기준 변경은 선택한 값·이유·출처/확인일을 `delivery_spec`에 기록한다.

## 읽기·크기·타이밍 (스튜디오 권장값)

| 항목 | 시작 기준 | 측정과 예외 |
|---|---|---|
| 일반 한글 문구 | 최소 안정 노출 `max(1.0, N/6 + 0.3)`초 | N은 공백/구두점 제외 한글 음절 수 + 영문/숫자 등 나머지 보이는 문자 수. 영문/날짜도 비용을 포함하는 보수적 휴리스틱. 고유명사·교육 기간·첫 등장 용어는 더 확보. 흔들림·마스크·가림·입퇴장은 안정 노출에 포함하지 않는다. |
| 자막 | 1~2줄, 구·발화 단위, 위 노출 권장값과 발화 길이 함께 확인 | 단어 강조가 너무 짧으면 전체 문장/구를 별도로 안정 노출. 자막이 발화를 크게 늦추지 않도록 대본을 줄이고 다시 타이밍한다. |
| 본문/자막 크기 | 출력 높이 H의 2.8% 이상부터 설계(1920H 약 54px em) | 제목 4~7%, 보조 정보 2.2% 이상부터. em은 실제 글자 높이가 아니므로 글꼴/획/대비·폰 실기기 화면으로 확인. 가로/정사각 비율은 별도 재설계. |
| 로고 정착 | 1.0초 이상 | 로고 스팅거 포함 식별 목적. 복잡한 워드마크는 더 확보. |
| 엔드카드 CTA | `max(2.0, 문구 최소 안정 노출)`초 | 로고·신청 날짜·신청 경로를 같이 읽는 경우 가장 긴 읽기 요구로 설계. 모든 장르에 CTA 의무 없음. |
| 컷/타이포 싱크 | 강조 사건 목표 오차 ±2프레임 | 자동 계산은 인계 타임코드의 차이만 보여준다. 실제 발음·의미와 지각적 싱크는 청취 확인. 의도적 선행/후행은 이유 기록. |
| 타임베이스 | 기본 30fps CFR, 실제 입력·납품이 요구하면 변경 | 24/25/50/60 등을 일괄 재타이밍하지 않는다. fps 유리수·총 프레임·지속시간·타임코드를 기록. 짧은 UI 지속시간도 프레임 양자화. |

이 식은 공인 한국어 독서 속도 규격이 아니다. 작은 글자를 오래 띄우거나 배속을 낮추는 것으로 어려운 문장을 해결하지 않는다. 정보량·문장·레이아웃부터 수정한다.

## 플랫폼 UI 가림

Reels·Shorts의 UI는 게시 방식(광고/일반), CTA, 기기, 자막 확장에 따라 달라진다. `safe_zone_profile`에 플랫폼·게시 방식·화면 비율·출처·확인일·제외 직사각형을 기록하고 실제 배치 미리보기로 확인한다.

| 프로필 | 현재 적용 가능한 설계 값 | 근거 상태 |
|---|---|---|
| Instagram/Facebook Reels 광고 | 상단 15%, 하단 40%, 좌우 8%를 중요 문구/로고에서 비우는 임시 시작값 | **스튜디오 보수적 권장**, 공식 숫자로 주장하지 않음. [Meta 광고 가이드](https://www.facebook.com/business/ads-guide/update/video/instagram-reels/outcome-engagement)는 이 환경에서 로그인으로 리다이렉트되어 공식 수치 미확인. 게시 전 현행 배치 미리보기 필요. |
| YouTube Shorts 세로 | 상단 15%, 하단 35%, 좌측 6%, 우측 20%를 비우는 임시 시작값 | **스튜디오 보수적 권장**. [Google 세로 광고 안전영역 자료](https://services.google.com/fh/files/misc/universalsafezones-youtube.pdf)는 이번 확인에서 fetch 실패. 일반 Shorts 전체에 동일한 공식 경계가 있다고 주장하지 않음. 기기/게시 방식 미리보기 필요. |

백분율은 프레임 경계로부터 거리다. 예: 1080×1920의 임시 Shorts 안전 직사각형은 x≈65~864, y=288~1248. 중요한 글자/CTA는 전체 bbox가 들어가게 하고 오른쪽 버튼·하단 설명을 피한다. 배경/비핵심 피사체까지 무조건 그 안에 가두지 않는다. 실제 확인이 없으면 플랫폼 가림 검수는 미확인이다.

## 무음·접근성

- 무음으로 핵심 메시지/행동이 성립하는지 독립 검수한다. 발화가 의미를 운반하면 자막을 제공하고 이해에 필요한 비발화 소리도 표현한다. 하드 자막과 SRT/VTT 필요 여부, 자동 자막 중복을 구분한다. [W3C 사전녹화 자막 기준](https://www.w3.org/WAI/WCAG22/Understanding/captions-prerecorded.html)을 참고한다.
- 글자 대비 설계는 [W3C 대비 기준](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)을 참고한다(일반 글자 4.5:1, 큰 글자 3:1). CSS의 큰 글자 정의를 영상 px/em과 등치하지 않는다. 움직이는 배경의 최저 대비는 단일 스타일 프레임으로 검증되지 않는다.
- 고대비/적색 점멸을 설계에서 피한다. [W3C 2.3.1](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)은 임의 1초에 3회 초과 점멸이 없거나 일반/적색 점멸 임계값 미만일 것을 요구한다. 면적·휘도·색·루프 경계 평가가 필요하므로 콘택트시트만으로 준수 판정하지 않는다. 현재 도구에는 전수 광과민성 검출이 없다. 위험한 연출은 제거하거나 검증 가능한 도구/전문 검수로 넘긴다.

## 출력·오디오·고지

| 항목 | 납품 원칙 |
|---|---|
| 비율 | 9:16(기본 1080×1920), 16:9(1920×1080), 1:1(1080×1080)을 별도 레이아웃/타이밍으로 리프레이밍. 단순 중앙 크롭으로 글자·행동·축·범례를 잘라내지 않는다. 요청된 비율만 제작. |
| 웹 마스터 | 스튜디오 기본 MP4/H.264 High, yuv420p, progressive, CFR, SDR BT.709(태그·실제 변환 일치), AAC-LC 48kHz stereo, faststart. [YouTube 권장 업로드 설정](https://support.google.com/youtube/answer/1722171)을 참고하되 다른 플랫폼의 보편 규격으로 주장하지 않는다. 비트레이트는 해상도/움직임과 납품서에 맞게 정한다. |
| 편집 소스/알파 | 사용 글꼴/라이선스·레이어 소스·프로젝트·실제 render_settings 보존. 투명 소스가 필요할 때 알파 지원 코덱/이미지 시퀀스를 별도 선택; H.264 파일에 알파를 약속하지 않는다. |
| 소셜 오디오 | 스튜디오 믹스 시작값 integrated −16 LUFS ±1, true peak ≤−1.5 dBTP. 플랫폼 공식 표준이 아니며 실제 인코딩 파일을 측정. 음악/음성/SFX 스템과 사용권 출처 보존, 청취로 덕킹·명료도·피로도 확인. |
| 방송 납품 | 방송사의 현행 납품서 우선. EBU R128 적용 납품이면 integrated −23 LUFS, 선형 PCM true peak ≤−1 dBTP를 참조. 짧은 방송물은 max short-term −18 LUFS 등 추가 요구 확인. [EBU 제작 지침](https://tech.ebu.ch/docs/tech/tech3343.pdf). 웹 믹스를 그대로 방송용이라고 이름 붙이지 않는다. |
| 측정 | [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I/en)는 라우드니스/true peak **측정 알고리즘**이며 소셜 플랫폼의 목표 LUFS를 정하는 규격이 아니다. 측정 도구·버전·전체 구간·예외(무음, 너무 짧은 파일)를 기록. |
| 고지 문구 | 확인된 의무 문구와 게시처 규정을 Fact & Rights가 확인. 글자 크기·노출 시간을 관행으로 임의 확정하지 않는다. 미확인 권리는 해당 출고 차단. 공간 부족이면 문장/장면을 재구성하고 고지를 숨기지 않는다. |
