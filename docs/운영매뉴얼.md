# 운영 매뉴얼

## 시작과 역할 호출

`python3 -m studio doctor`로 설치/버전/남은 공간을 먼저 확인한다. `examples/brief.json`을 참고해 제작 ID, 브랜드, 핵심 문장, 시청자 질문, 분량, 설정을 정한다. 이번 구축에서는 주제를 정하지 않았고 기술 fixture만 렌더했다. `init BRIEF`는 새 원장을 만들고 기존 ID가 있으면 차단한다. `status ID`는 현재/MISSING/STALE과 QA 차단 이유, `resume ID`는 재사용 가능한 단계와 다음 준비된 단계를 보여준다. resume는 계획 출력이고 미연결 생성기를 자동 호출하지 않는다.

로컬 Codex를 프로젝트에서 열고 Producer를 명시 호출한다. `agent-plan ROLE --id ID`는 역할 지침과 이전 파일 인계 컨텍스트를 반환한다. 역할 TOML은 공식 네이티브 형식이다. `.agents/skills/`의 프로젝트 스킬은 지침이며 Python 함수/API가 아니다. 모든 자식은 읽기 전용이고 Producer가 파일을 저장한다. 필요할 때만 단계 전문가를 호출한다. 글로벌 개인 에이전트 정의와 개인 스킬은 수정하지 않았다.

## 단계 인계

|단계|산출물|다음 입력|
|---|---|---|
|Research|관찰 구분과 Hook/Curiosity/Shot/Visual Focus/Text/Caption/Motion/Transition/Sound/Payoff 분석|Fact, Script|
|Fact & Rights|주장별 출처와 실제 사용권|Script, Asset, Audio|
|Story & Script|핵심 문장/시청자 질문, 사건 대본|Shot, Voice|
|Director|모든 Shot 필드와 시선/새 정보/전환 이유|Art, 3D, Motion|
|Art|레이어 에셋과 스타일 검수|Motion|
|3D, Motion|공간·가림·카메라·사건 모션과 렌더|Editor|
|Voice|현재 대본 한국어 후보 비교와 선정 음성|Caption, Audio|
|Audio|분리 스템과 믹스|Editor|
|Editor & Caption|현재 VIDEO와 JSON 자막|독립 QA|
|Technical QA, Viewer QA|정확한 현재 스냅샷 검수|Recovery & Release|

인계에 production ID, artifact ID, 파일 경로/해시, 입력 의존성, 실행 상태와 품질 상태, 근거, 다음 단계 행동을 남긴다. `ingest ID KIND FILE --author 제작자ID`로 산출물을 등록한다. 같은 단계의 모든 에셋/스템/장면 파일은 하나의 ZIP 번들로 묶어 등록할 수 있다. 외부 파일을 참조하는 JSON만 등록하면 참조 파일 자체는 원장에 포함되지 않으므로 출고 금지: 파일을 번들에 포함해야 한다. 실행기는 JSON 내부의 임의 참조 파일까지 자동 추적하지 않는다. Asset/Audio를 다중 파일 번들로 등록하고 해시를 통째로 고정하는 운영 계약이다.

현재 단계 컨텍스트와 설정을 파일에 포함하고 대화 요약만으로 진행하지 않는다. immutable 스냅샷/이벤트/실패 기록을 공유한다. 상업권 미확인, 외부 도구 미연결, 실제 검수 불가 상태는 BLOCKED로 남긴다. 이미지 생성 수나 창작 개선 횟수에 임의 제한을 두지 않는다.

## 미디어 제작

Blender는 구조·실제 물체 운동·공간 관계·가림·카메라 이동 의미가 있을 때 사용한다. `blender-fixture OUTPUT --frames 36`은 기술 장면 검증용이며 실제 Shot 생성 템플릿과 다르다. Python 스크립트를 프레임 기반으로 작성하고 장면 파일을 번들에 보존한다. `compose MANIFEST OUTPUT`은 로컬 PNG의 정적 레이어 합성 어댑터이며 완성 모션 생성기가 아니다. BACKGROUND부터 투명 레이어 순서를 지정한다. 동적 모션은 Blender 또는 승인된 별도 렌더 구현이 담당한다. Remotion 런타임은 현재 미연결이다.

`captions JSON OUTPUT --duration 초`로 1~2줄 발화 JSON을 SRT로 출력한다. `mix MANIFEST OUTPUT.wav`로 VOICE와 필요한 스템을 믹스하고 원본은 보존한다. 정확한 텍스트 중복은 자동 차단하지만 의미 중복·가독성·싱크·믹스 품질은 실제 검수다.

한국어 후보는 `voice-candidate TEXT VOICE OUTPUT --speed 180`으로 기술 생성 가능하다. 설치된 Yuna와 Eddy 후보 파일을 생성했지만 직접 청취와 라이선스 확인이 끝나지 않았다. 후보 비교 파일의 발음/억양/속도/감정/피로도/라이선스를 실제 확인한 뒤 선택한다. 로컬 음성을 낮은 품질 대체재로 자동 채택하지 않는다. 클라우드 TTS/이미지 생성은 비용·키 승인 후 연결해야 한다.

VOICE/BGM/AMBIENCE/IMPACT/WHOOSH/OBJECT/TRANSITION SOUND를 필요한 만큼 분리하고 믹스 전 실제 청취한다. 자막은 짧은 발화 1~2줄, 모바일 가독성과 싱크. TITLE/INFOGRAPHIC TEXT/BURNED CAPTION/PLATFORM CAPTION 의미 중복을 확인한다. 모든 프레임·레이어·오디오가 현재 입력인지 확인한 뒤 렌더한다.

## QA와 출고

최종 렌더가 등록된 뒤 `qa-template ID 'Viewer QA' --reviewer 독립검수자`를 출력해 현재 해시를 확인한다. 다른 9개 게이트도 각각 독립 보고서를 준비하고 `qa ID REPORT.json`으로 등록한다. QA 보고서 파일도 생성 전 저장 위치·경로를 확인한다. 보고서의 모든 필수 check가 True, 근거가 존재, snapshot이 현재여야 PASS가 등록된다. Technical QA와 Viewer QA는 제작자와 다른 ID, observed_video/observed_audio 모두 True가 필요하다. 체크만 True로 고쳐 통과시키지 않는다. 이것은 신뢰받는 로컬 운영자의 실제 관찰 선언이며 암호학적 신원 인증이나 인간 관찰 자동 증명 기능은 아니다.

시청자 검수는 첫3초·5초 이후 새 정보·화면/말 반복·자막만 남는 콘텐츠 여부·시선·마지막 회수를 시간별 평가한다. 실제 영상을 재생하고 음성을 듣지 못하면 BLOCKED. 실행 성공은 decode/렌더 성공이며 창작 품질이나 실제 시청률을 보장하지 않는다. 하나라도 FAIL/BLOCKED/MISSING/STALE이면 출고되지 않는다. 모든 현재 산출물도 필요한 상태다. fixture 및 fixture로 표시된 산출물은 품질 PASS 제출 자체가 차단되며 출고도 금지다. 알려진 fixture 해시/sidecar/부모 디렉토리 표식이 복사된 산출물에 전파된다. 기술 도구는 실행 전에 fixture 표식을 만들어 실패 잔여물도 표시한다.

`release ID`는 `runs/ID/FINAL/<snapshot>/`에 PROJECT/ASSETS/AUDIO/SCRIPT/SHOT/RESEARCH/QA/FAIL/LOG와 video.mp4, 해시 목록 release.json을 묶는다. 복사 후 해시를 확인하고 원자적으로 패키지를 완성한다. 같은 스냅샷 재출고는 같은 경로를 반환한다. 공개/업로드는 구현하지 않았다.

## 캐시·복구

캐시의 정체성은 SCRIPT/FACT/SHOT/ASSET/VOICE/CAPTION/VIDEO/AUDIO의 제작 ID/버전/파일 SHA256, 직접 의존 ID/해시, voice model/style/speed/shot/asset/caption/render/tool 버전 설정, 실행 코드·역할·스킬·스키마와 실제 로컬 바이너리 서명이다. 바이너리 경로/크기/수정시간도 확인해 도구 변경을 감지한다. 도구 설정은 doctor 결과와 맞춰 입력한다. 실행기는 캐시된 현재 산출물을 resume에서 재사용하고 자동으로 낡은 파일을 다시 사용하지 않는다. 별도 고성능 render cache 서버는 없다.

SCRIPT가 바뀌면 SHOT→ASSET→MOTION→VIDEO 및 VOICE→CAPTION/AUDIO→VIDEO가 STALE이다. ASSET만 바뀌면 MOTION/VIDEO만 STALE이고 Research/Fact/Script/Voice 등은 유지한다. 설정/도구/코드 변경은 보수적으로 해당 제작 전체를 STALE로 만든다. 모든 QA는 최종 전체 스냅샷과 결합하여 어떤 수정에도 재검수를 요구한다.

`recover ID ASSET --problem 잘림 --hypothesis 전경위치수정`은 실패를 보존하고 변경할 단계와 유지할 단계를 계획한다. 실제 수정은 관련 레이어를 고친 뒤 ingest하고 재렌더한다. 자동 창작 복구 모델은 아직 연결하지 않았다. 같은 실패에 과거에 사용한 같은 가설을 다시 제출하면 차단한다. 실패 기록을 생성하면 이전 QA는 STALE이 된다. FAIL 원인·단계·문제·수정·교훈·다음 가설을 기록하고 실제 진단 전 원인을 단정하지 않는다. WATCH→문제 감지→레이어 식별→부분 수정→재렌더를 반복한다.

## 확장과 저장 정책

3초 Hook→8초 prototype→1편→QA/개선→스타일 변형→3~5편→QA→대량 제작 순서다. 자동 대량 생산은 품질 게이트를 우회하지 않는다. 스타일은 색뿐 아니라 구도/타이포/카메라/모션/에셋/리듬/음향/전환으로 구분한다. 이 확장 정책은 Producer/스킬의 운영 계약이고 CLI가 창작 적합성을 자동 판단하지 않는다.

사용자가 지정한 프로젝트에 구축했다. 필수 등록 규칙과 추가 승인을 확인하여 전역 REGISTRY/맵의 프로젝트 참조, pipeline-short-studio 스킬, 체크포인트 링크를 추가했다. 전역 보안 정책·기존 에이전트·모델 설정은 변경하지 않았다. 최종 파일은 명시 지정한 프로젝트 runs에 저장한다. 민감 brief와 캐시는 로컬 runs에 있으며 보안을 위해 gitignore 처리했지만 암호화 저장소는 아니다. OS 접근 제어와 사용자의 보존정책을 따른다. 메모리 요약·자격증명·계정 설정은 수정하지 않는다.

## 광고 제작 정책

[실사·카피·영상미 기준](advertising-creative-standard.md)이 두 도구의 공통 창작 기본값이다. config/studio.json의 creative_direction을 새 제작 계획에 반영하고 brief.creative_direction의 명시적 방향으로 재정의한다. agent-plan은 해당 방향과 정책 문서를 프롬프트에 인계한다. 기술 fixture에는 광고 기본값을 적용하지 않는다. 실제 이미지/영상 생성은 승인된 연결 도구로 Producer가 수행하며 PLAN_ONLY 출력은 생성/품질 통과가 아니다. 모션그래픽은 [전문 기준](motion-design-standard.md)을 읽고 제작한다. 정책/스킬/역할/코드 변경으로 기존 원장이 STALE이 될 수 있으며 이전 제작물·원장·승인을 수정하지 않는다.

## 모션 애니매틱과 검수 증거

모션은 [장르 부록](motion-genres.md)에 맞추고 스타일 프레임→스토리보드→사전 애니매틱→모션 토큰→본 애니메이션 순으로 전체 리듬을 설계한다. 3초/8초 프리뷰와 애니매틱을 구별한다. [정량·납품 기준](motion-delivery-spec.md)의 권장값은 공식 플랫폼 규격이 아니다. [2층 검수](motion-review-protocol.md)에 따라 `python3 scripts/motion_review_evidence.py --video CURRENT.mp4 --output-dir NEW_QA_DIR --manifest motion-review-input.json`으로 실제 측정 증거를 저장하고 현재 VIDEO SHA와 비교한다. 자동 증거는 미시청을 관찰로 바꾸지 않으며 관찰 QA만 BLOCKED/사람 검수 대기로 남긴다. 독립적인 정상 속도 시청·청취와 무음 확인 전 초안 상태를 유지하고, 가능한 수정·날짜/시간별 저장은 계속한다. 이 진행 표현은 새 CLI QA enum이 아니며 기존 게이트·release 조건을 유지한다.
