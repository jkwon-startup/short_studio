# 숏폼 디자인·음악 사전 제작 기준

Producer와 Art/Motion/Audio는 렌더 전 이 문서를 읽는다. Codex와 Claude에서 같은 디자인 패킷을 사용할 수 있으며 실행 도구와 과금 승인은 별도로 점검한다.

## 디자인 스킬과 브랜드 읽기

동봉한 `design-skills/frontend-design/SKILL.md`를 사용한다. 이 스킬은 시각 정체성·타이포그래피·레이아웃을 설계하고, 제작 전 계획을 비판적으로 검토하도록 한다. 웹 레이아웃을 영상에 그대로 넣지 않는다. 실제 브랜드 맵·글꼴·색·로고가 제공되면 그 근거를 먼저 읽는다. 없는 브랜드 규칙을 임의로 만들어 원본이라고 부르지 않는다.

실제 설치된 글꼴 파일과 사용권을 확인하고, 브랜드 지정 글꼴이 없으면 대체 이유를 기록한다. 글꼴 이름 교체만으로 개선을 주장하지 않는다. 굵기·행간·글자 크기·정렬·화면 면적을 역할별로 설계하고, 실물 UI 글자·핵심 사건·보조 문구를 구별한다. 화면마다 같은 큰 제목·중앙 카드·상시 브랜드·번호·진행바를 반복하지 않는다.

## Producer가 남길 디자인 패킷

브랜드/시청자/핵심 사건, 4~6개 색의 역할, 실제 글꼴과 굵기·크기·행간, 장면별 시점과 주시 대상, 움직임의 사건상 이유를 `design-packet.json`에 남긴다. 계획이 어떤 주제에도 붙일 수 있는 기본 카드 구성인지 다시 검토한다. 과도한 설명·중복 제목을 줄이고, 구도와 사건을 변경해 차이를 만든다.

대표 스타일 프레임을 실제 렌더에서 확인한다. 첫 화면, 문제/결과, 입력 또는 수정, 회수의 서로 다른 구도를 비교한다. 같은 구도라면 의도와 필요를 설명한다. 검토되지 않은 계획이나 일부 정지 이미지로 디자인 승인·몰입 PASS를 주지 않는다. 사용자가 스타일을 거부한 제작은 실패 기록과 원본을 보존하고, 새 복구 가설과 별도 시제품으로 진행한다.

## 음악도 사전 제작에 포함

실제 제작에서 사용자가 BGM 부재를 문제로 평가한 사례가 있다. 이 브랜드의 다음 시제품에는 BGM 계획·실제 스템·적용 여부를 확인한다. 모든 장르에 획일적인 BGM 의무를 만들지는 않는다. 사용자가 정적이나 음악 없는 구성을 요청하면 그 의도를 우선한다.

BGM/음성/효과음은 별도 스템으로 저장한다. 곡의 출처와 사용권, 템포·음색·화음·사건별 층 변화, 시작/끝 처리와 음성 공간을 기록한다. 음악과 컷을 억지로 같은 숫자 간격에 맞추지 않는다. 원본 작곡·합성도 실제 음악 청취가 필요하다. LUFS·true peak·비클리핑·파일 존재만으로 음악 품질 PASS를 주지 않는다. 음성이 생기면 음악 레벨을 다시 믹스한다.

## 도구 점검의 근거

`doctor` 출력의 고정 문자열만으로 미연결·연결을 결론내리지 않는다. 설치/설정 존재, 과거 생성 증거, 현재 실제 호출, 비용 승인, 사용권을 구분한다. 프로젝트 공통·도구별 어댑터를 읽고 확인된 버전과 상태를 기록한다. 다른 세션의 키나 계정·과금 승인은 자동 승계하지 않는다. 키 값을 보고서에 담지 않는다.

## 확인과 적용

첫 3초·8초 파일을 실제 속도로 재생·청취하고, 입력과 결과의 이해·반복 구도·읽기 시간·음악의 피로도와 동기를 검토한다. 실제 관찰이 없으면 BLOCKED. 기술 측정과 프레임 리뷰는 별도의 부분 근거로 보존한다. 이번 개선이 성공했는지는 사용자의 평가와 실제 관찰로 확인한다.

향후 공통 제작 스킬에 통합할 때에는 이 문서의 원칙을 호출하도록 연결하고 기존 제작의 설정/의존 해시 변화와 QA를 관리한다. 동시에 진행 중인 다른 제작의 스킬·엔진·어댑터를 덮어쓰지 않는다.

## 광고 제작 기본 방향

[실사·카피·영상미 기준](advertising-creative-standard.md)을 먼저 적용한다. 기본은 인물·행동·빛·구도가 있는 실사풍 광고이고 브랜드 타이포·일정/UI 그래픽은 필요한 장면을 돕는다. 도구가 편하다는 이유로 도형 시제품을 전편 표현으로 고정하지 않는다. 모션그래픽을 선택하면 [전문 모션 기준](motion-design-standard.md)의 타이포·안무·이징·합성·사운드와 실제 렌더를 인계한다.
