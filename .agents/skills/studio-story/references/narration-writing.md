# 숏폼 내레이션 글쓰기 기준

Story & Script 단계가 대본을 쓸 때 따르는 기준이다. 운영 절차(원장·해시·STALE)는 SKILL.md, 장면 리듬은 `../studio-produce/references/attention-and-pacing.md`가 맡는다. 이 문서는 **무엇을 어떻게 말할지**를 정한다.

도입 배경(2026-10-02): 첫 대본이 "내용이 약하고 어색하다", "자막처럼 끊긴다"는 사용자 평가를 받았다. 원인은 메시지 2개 혼합, 장면 먼저·말 나중 작성, 맥락 없는 수치 삽입, 글쓰기 기준 부재였다.

## 1. 메시지 하나를 먼저 고정한다

- core_sentence는 **한 문장, 한 메시지**다. "A지만 B" 식으로 두 주장을 묶었다면 쓰기 전에 Producer에게 되돌린다.
- 시청자가 영상을 다 보고 나서 한 문장으로 말할 수 있어야 한다. 그 문장이 core_sentence와 같은지 마지막에 확인한다.
- 메시지와 직접 관계없는 정보(흥미로운 사실, 다른 각도)는 다음 편 소재로 넘긴다.

## 2. 콘텐츠 유형을 고르고 구조를 맞춘다

HOOK→EVENT→DISCOVERY→ESCALATION→PAYOFF는 장면 설계용 틀이다. 말의 흐름은 유형별로 고른다. 메시지가 '가능성'인데 억지로 사고·위기를 만들어 넣지 않는다.

| 유형 | 언제 | 말의 흐름 |
|---|---|---|
| 가능성·동기부여 | "누구나 할 수 있다" | 공감되는 막힘 → 오해 깨기 → 가능하다는 근거(장면·사례) → 현실적인 기대치 → 오늘 할 첫 행동 → 브랜드 |
| 경고·주의 | "이것만은 조심" | 흔한 실수 장면 → 왜 생기나 → 얼마나 흔한가(근거 1개) → 막는 방법 → 독려 |
| 방법·튜토리얼 | "이렇게 하세요" | 구체적인 불편 → 입력 예시 → 눈에 보이는 결과 → 다음 불편 → 수정·회수 |

기본 글쓰기 순서(환상 깨기 → 현실적 기대치 → 실전 방법)는 세 유형 모두에 녹인다. 장밋빛만 말하지 않고 한계를 한 번은 솔직하게 말한다.

## 3. 말을 먼저 쓰고, 장면은 그 다음에

- 내레이션 전체를 **귀로만 들어도 이해되는 이어진 말**로 먼저 완성한다. 그다음 문장마다 장면을 붙인다. 장면을 먼저 정하고 말을 끼워 넣으면 자막처럼 끊긴다.
- 문장끼리 이어 주는 말(그런데, 그래서, 대신, 물론)을 지운 채 명사로 끝내지 않는다. "개인정보 노출 175건." 같은 명사 종결 나열은 자막용이지 내레이션이 아니다.
- 한 문장에 생각 하나. 주어와 서술어가 멀어지면 나눈다.
- 화면 없이 들어도 뜻이 통해야 한다. "남의 폰엔"처럼 화면을 봐야만 이해되는 지시어는 풀어 쓴다.
- 분량 기준: **약 7자/초(공백 포함). 30초 = 약 210자, 60초(가로형 기본) = 약 420자**(실측: 공백 포함 248자에 35초, ElevenLabs 속도 1.0). 글자 수는 **반드시 공백·문장부호 포함**으로 센다(ElevenLabs 과금 기준과 같음). 공백 없이 센 음절 수로 분량을 판단하지 않는다. 글자 수를 맞추려고 연결어를 잘라 내지 않는다. 넘치면 정보를 덜어 낸다.

## 4. 브랜드 목소리

- brief와 `config/local.json` brand.tone의 브랜드 톤을 따른다. 브랜드 프로필이 없으면 대상에 맞는 정중하고 쉬운 말투를 쓴다.
- 기본 말투는 합니다체. 한 대본 안에서 해요체·반말과 섞지 않는다.
- 독자에게 말 걸듯 시작하고, 비유는 한 대본에 한 번만 제대로 쓴다.
- 결말은 겁주기나 훈계가 아니라 다음 행동을 권하는 말로 끝낸다.

## 5. 사실은 메시지를 받칠 때만

- fact.json의 VERIFIED 사실과 safe_wording만 쓴다. forbidden_wording은 쓰지 않는다.
- 사실이 메시지의 어느 주장을 받치는지 한 줄로 설명할 수 없으면 넣지 않는다. 앞뒤 문장과 이어지지 않는 수치·수상 이력은 빼는 편이 낫다.
- 숫자는 영상 하나에 1~2개. 숫자는 화면 그래픽이 맡고, 말은 그 숫자가 시청자에게 무슨 뜻인지를 말한다.
- 팁·의견은 사실처럼 말하지 않는다("전문가들이 입증한" 금지).

## 6. AI 티 나는 표현 걸러내기

아래는 [im-not-ai / Humanize KR](https://github.com/epoko77-ai/im-not-ai)(MIT License, © 2026 epoko77-ai)의 한국어 AI 문체 분류에서 **내레이션에 해당하는 항목만 골라 숏폼용으로 요약·각색한 것**이다. 괄호 안은 원 분류 ID다. 원 프로젝트는 '다 쓴 글의 윤문' 도구라서, 여기서는 **처음 쓸 때부터 피하는 기준**으로 바꿔 쓴다.

**번역투**
- "~을 통해", "~에 있어서", "~와 관련하여", "~에 기반하여"를 쓰지 않고 조사로 바로 잇는다. "AI를 통해 앱을 만든다" → "AI로 앱을 만든다" (A-1·3·5·6)
- "가지고 있다", "~에 의해 만들어진", "~되어진다" 대신 능동문. "AI에 의해 생성된 화면" → "AI가 만든 화면" (A-7·8·9)
- 추상 주어 + 만능 동사("기술이 가능성을 제공합니다")를 피하고 사람을 주어로 쓴다 (A-15·D-5)
- "단순한 X를 넘어 Y", "더 이상 ~이 아닙니다"를 만들지 않는다 (A-21·24)

**AI 관용구**
- "결론적으로", "주목할 만합니다", "시사하는 바가 큽니다", "혁신적인"을 쓰지 않는다 (D-1·2)
- "~할 때입니다", "~하는 시대입니다", "X에서 Y로" 같은 결말 공식은 대본당 한 번 이하. 가능하면 구체적인 행동 권유로 바꾼다 (D-6·7)
- "핵심은 ~입니다", "중요한 것은 ~입니다" 분열문 대신 바로 말한다. "중요한 건 기획입니다" → "기획부터 하세요" (D-8·I-2)
- "~하는 이유입니다", "~라는 것입니다"로 끝내지 않는다 (D-10·I-3)
- 사전식 은유(청사진, 신호탄, 뿌리내리다)를 쓰지 않는다. 비유는 일상의 구체적인 사물로 한 번만 (D-14)

**구조·리듬**
- "A가 아니라 B", "A일까요, B일까요" 대구는 대본당 한 번만 (C-8)
- "첫째, 둘째, 셋째" 나열을 쓰지 않는다. 30초 안에서는 하나만 깊게 (C-9·D-3)
- 같은 종결어미가 네 문장 넘게 이어지지 않게 한다("~습니다." 연속 → 질문, 권유, 짧은 단문을 섞는다) (E-2)
- 문장 길이를 고르게 맞추지 않는다. 짧은 문장과 조금 긴 문장을 섞어 말의 리듬을 만든다 (E-1)
- "~할 수 있습니다"를 반복하지 않는다. 반복되면 일부를 다른 표현으로 바꾸되, 가능성을 단정으로 바꾸지는 않는다 (A-10·G-1)
- 명사화("-성", "-화", "-적 N")를 줄이고 동사로 말한다. "창업의 대중화" → "누구나 창업합니다" (F-4·5)
- 연결어미 뒤에 쉼표를 찍지 않는다. "만들고, 고치고," → "만들고 고치고" (C-11)

**반대로, 하지 말 것**
- 위 기준을 지키려고 원래 말하려던 내용을 바꾸거나 수치·고유명사를 고치지 않는다.
- 없던 비유나 수사를 새로 집어넣어 '사람 같아 보이게' 꾸미지 않는다.

## 7. TTS용 표기

- `tts_text`를 따로 만든다. 자막과 화면은 숫자(2025, 5,600)를 쓰고, tts_text는 읽는 대로 한글로 쓴다("이천이십오 년", "오천육백 개", "백칠십오 건").
- 영어 약어는 읽는 방식을 확인한다(AI → 에이아이로 읽히는지). 이상하면 tts_text에서만 한글로 쓴다.
- 쉼이 필요한 곳은 문장을 끊어서 만든다. 쉼표를 남발하지 않는다.

## 8. 작성 절차와 자체 점검

1. core_sentence와 콘텐츠 유형을 확인한다(1·2절).
2. **훅 문장 3개**를 쓴다. 각각 첫 3초 장면과 짝지어 둔다.
3. **전체 초안 2개**를 쓴다(다른 훅, 다른 흐름).
4. 각 초안을 아래 체크리스트로 점검하고, 고친 결과와 함께 둘 다 Producer에게 넘긴다. 추천안과 이유를 한 줄로 단다.
5. Producer가 추천안을 선택하고 [프로젝트 자동 진행 규칙](../../../../AGENTS.md#자동-진행과-승인-재사용)을 따른다. 사용자가 자동 제작을 맡긴 경우 추천 대본 선택의 사전 승인을 기록하고 매번 확정을 묻지 않는다. 사용자가 검토 후 진행을 요청한 경우만 대본 확인을 기다린다. Voice 단계는 별도로 승인된 provider·설정·한도·사용권 안에서 진행하며 대본 승인과 비용 승인을 구별한다.

**체크리스트**(초안마다 결과를 출력에 남긴다)
- [ ] 다 듣고 나서 한 문장으로 말하면 core_sentence와 같은가
- [ ] 화면 없이 소리만 들어도 이해되는가
- [ ] 소리 내어 읽었을 때 걸리는 문장, 자막처럼 끊기는 명사 종결이 없는가
- [ ] 문장끼리 이어지는가(갑자기 다른 화제가 끼어들지 않는가)
- [ ] 메시지와 관계없는 사실·수치가 없는가
- [ ] 6절 AI 티 표현이 남아 있지 않은가(남았다면 어느 항목인지 표기)
- [ ] 브랜드 톤과 합니다체가 일관되는가
- [ ] 결말이 행동 권유로 끝나는가
- [ ] 분량이 공백 포함 약 7자/초(30초 ≈ 210자, 60초 ≈ 420자) 이하이고 tts_text가 있는가 — 글자 수는 공백 포함으로 센 값을 표기

## 9. 출력에 추가할 필드

기존 SCRIPT 필드에 더해 `content_type`, `hook_options[3]`, `drafts[2]`(각각 full_narration, tts_text, 글자 수, checklist 결과), `recommended`(어느 초안, 이유), `one_line_takeaway`(시청자가 기억할 한 문장)를 넣는다.

## 10. 광고 카피 추가 인계

[광고 공통 기준](../../../../docs/advertising-creative-standard.md#2-광고-카피-한-사람에게-한-행동을)을 적용하고 SCRIPT에 ad_copy_review를 더한다. 타깃의 구체적인 망설임·제공 가치·믿을 이유·훅/장면 연결·차별 카피·CTA·추천 이유를 점검한다. 기존 im-not-ai 출처·체크리스트·자연스러운 내레이션·자동 진행 규칙을 유지한다. 관련성/근거 없는 충격 훅이나 상투적 질문을 글쓰기 규칙을 통과했다는 이유로 채택하지 않는다.
