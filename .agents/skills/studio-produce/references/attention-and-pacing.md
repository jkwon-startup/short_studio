# 정보류 숏폼의 몰입과 리듬

## 적용 범위와 근거

이 스튜디오의 정보류 숏폼은 시청자가 다음 장면을 기다릴 이유를 만드는 것을 기본 목표로 한다. 사용자가 차분한 설명, 긴 관찰, 다른 장르·속도를 요청하면 그 의도를 우선한다. 컷 수·속도·음악 취향을 모든 콘텐츠에 동일하게 적용하지 않는다.

2026-10-02 실제 사용자가 기존 30초 초안에 “영상이 너무 느려서 유저들이 넘겨버릴 것 같고 너무 재미없어”라고 피드백했다. 이는 속도·몰입에 대한 사용자 평가이며 측정한 이탈률이나 실제 시청률 데이터가 아니다. 정지 카드·작은 휴대폰·상단 제목을 반복하는 구성과 긴 정보 공백을 검토할 계기로 사용한다.

## Producer: 렌더 전에 사건과 리듬을 설계

- 첫 프레임부터 타깃이 알아볼 문제, 충돌, 결과 또는 의문을 장면으로 보여준다. 로고·주제 소개·추상적인 준비 설명으로 첫 3초를 소비하지 않는다. 훅의 문장과 실제 화면 사건이 연결되어야 한다.
- SCRIPT/SHOT에 비트 타임라인을 남긴다. 각 비트에는 시간, 사건, 새 정보, 시청자의 다음 질문, 주시 대상, 구도, 움직임 이유, 음향 사건을 적는다. 정지·긴 읽기 구간은 `hold_reason`으로 의도를 설명한다. 기존 Shot 필드에 추가하거나 별도 비트 파일로 인계할 수 있다.
- 실행법 영상은 구체적 불편 → 실제 행동·입력 예시 → 눈에 보이는 결과 → 추가 불편·피드백 → 수정·회수로 이어간다. 주제 이름을 바꿔 보여주기만 하는 장면은 새 정보로 세지 않는다. 가정한 고객 반응·UI는 예시로 표시한다.
- 짧은 행동·발견 비트는 대체로 1~2.5초를 설계 출발점으로 삼되, 실제 정보량과 모바일 읽기 시간에 맞춘다. 같은 구도·핵심 정보가 3초 이상 유지되면 독립 재생 검토 대상으로 표시한다. 숫자만으로 PASS/FAIL을 결정하거나 무조건 컷을 추가하지 않는다.
- 3초 훅과 8초 시제품에서 사건의 명료도, 다음 장면을 기다릴 이유, 읽기 시간, 반복 구도, 음향 리듬을 확인한다. 느리거나 의미 없는 반복이 발견되면 본편 확장 전에 대본·Shot을 수정한다. 사용자가 본편 초안을 명시 요청해 확장하더라도 미검수 초안을 품질 승인으로 표현하지 않는다.

## Story / Director / Motion / Editor: 변화를 사건으로 만들기

- 설명 문장을 행동 장면으로 바꾼다. 문제 발생, 선택, 입력, 생성, 실패 지점, 수정 전후처럼 내용상 다른 순간을 보여준다. 화면의 글자나 색만 교체하고 같은 구도를 계속 유지하지 않는다.
- 전체 상황, 손·버튼 근접, 입력 화면, 결과, 사용자 반응 등 내용에 맞는 시점·프레이밍을 선택한다. 작은 UI+큰 제목을 반복하는 정면 슬라이드를 구현이 쉽다는 이유로 기본 완성형으로 채택하지 않는다. 도형·카드도 실제 사건을 표현한다면 사용할 수 있다.
- 모션은 새로운 정보와 시선을 안내한다. 반복 줌, 상시 흔들림, 무관한 장식, 읽을 시간을 없애는 전환은 몰입 개선으로 세지 않는다. 밀도는 의미 있는 사건에서 확보한다.
- 글자는 짧은 발화 또는 한 행동 단위로 나누고 화면과 말의 중복을 줄인다. 긴 프롬프트는 읽을 시간을 주거나 핵심 입력 부분을 나눠 보여준다. 아무 새 정보 없이 페이드가 끝난 화면을 분량에 맞춰 오래 유지하지 않는다.
- 지루함 복구는 대본 압축, 비트 재배치, 구도·주시 대상 변화, 인과 관계와 결과 공개 시점부터 다시 설계한다. 전체 영상을 1.5배속으로 돌리거나 클릭음을 더하는 것만으로 해결했다고 판단하지 않는다.

## Audio: 소리도 내용의 리듬으로 설계

말의 강세·쉼, 사건 소리, 필요한 음악·의도적 정적의 관계를 비트 타임라인에 기록한다. 음성이 필요한 콘셉트인데 연결되지 않았다면 음성 완성을 BLOCKED로 남기고 무내레이션 초안의 한계를 밝힌다. 음악·음성의 사용권과 비용·연결 권한은 기존 규칙을 따른다. 같은 클릭이나 Whoosh를 반복하는 것은 이야기의 리듬을 대신하지 못한다. 실제 청취로 명료도·타이밍·피로도를 검수한다.

## Viewer QA: 기술 성공과 몰입 검수를 구분

- 현재 해시의 영상을 실제 속도로 연속 재생하고 모바일 크기로 읽는다. 음향도 실제로 듣는다. 첫 3초와 8초, 중간 정보 공백, 반복 구도, 입력·결과의 이해, 끝의 회수를 시간대별로 확인한다.
- 접촉시트·정지 프레임·디코드 성공·글자 안 잘림은 리듬·재미의 PASS 근거가 아니다. 정지 프레임만 확인했다면 `PARTIAL_FRAME_REVIEW_NOT_FINAL_QA`, 실제 연속 재생·청취를 못 했다면 해당 몰입 검수는 BLOCKED다. 관찰하지 않은 시청·청취를 선언하지 않는다.
- 보고서에 `first_3s_event`, `next_reason`, `long_holds`, `repeated_compositions`, `reading_windows`, `sound_rhythm`, `dropoff_risk_timecodes`, `observed_video_realtime`, `observed_audio`를 근거와 함께 포함한다. 기존 Viewer QA 보고서의 추가 근거 필드이며 CLI에 새 자동 게이트가 생겼다고 주장하지 않는다.
- 실시간 관찰에서 사건 없는 도입, 읽기 목적 없는 정보 공백, 반복 구성 때문에 늘어지는 구간, 과한 속도로 이해가 깨지는 구간을 발견하면 Viewer QA FAIL로 보고한다. 시간, 문제 레이어, 왜 기다릴 이유가 약한지, 새 복구 가설을 남긴다. 무음·무자막 상태를 장르 맥락 없이 무조건 FAIL로 만들지는 않는다.
- 사용자가 직접 “느리다·지루하다”라고 평가하면 현재 결과를 몰입 개선 대상으로 되돌린다. Producer는 사용자 피드백을 직접 확인 자료로 기록하고 STORY/SCRIPT/SHOT 중심으로 복구한다. 기술 검증이나 일부 프레임의 LOW 판정으로 사용자 평가를 반박하지 않는다.

이 기준은 편집 지침과 실제 관찰 계약이다. 시청 유지율이나 재미를 자동 측정·보장하지 않으며, 기존 FINAL/권리/최신 해시/FAIL 보존 규칙을 유지한다.

## 광고에서 적용

[광고 공통 기준](../../../../docs/advertising-creative-standard.md)의 실사 인물/행동·영상미·광고 카피·음향과 함께 리듬을 설계한다. 모션을 선택하면 [전문 모션 기준](../../../../docs/motion-design-standard.md)의 레이어 안무·이징·타이포·전환/소리까지 검수한다. 속도감 목표는 의미 있는 장면 변화이며 기계적인 컷 수나 TTS 배속 목표가 아니다.
